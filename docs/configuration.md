# Configuration Reference

Everything the gate reads from disk lives in `<agentDir>/config/pi-verdict.json` (first run generates a template there; `PI_CODING_AGENT_DIR` overrides the location). This page is the full reference; the README keeps a quick-start subset.

## User rules

```json
{
  "allow": ["^ls\\b", "^git (status|log|diff)\\b"],
  "deny":  ["rm ", "docker ", "^/etc/"],
  "tools": ["ask", "todo", "wait", "task", "yield", "think", "checkpoint", "rewind", "recall", "reflect"],
  "denyPaths": [
    "~/.ssh/",
    "~/.profile",
    "~/.gnupg",
    "~/.mc",
    "~/.zshrc",
    "~/.bashrc"
  ],
  "builtinDenyFloor": true,
  "gateOmpDir": true,
  "autoDeny": true,
  "classifierModel": null,
  "explainGateModel": null,
  "explainGatePrompt": null,
  "toggleShortcut": "ctrl+shift+a",
  "rules": []
}
```

- `allow`/`deny` are JS regex arrays; **`deny` wins over `allow`**, both beat the classifier. Match targets: bash/powershell = the full command string; file tools = the resolved absolute path (on Windows in POSIX form: `/` separators, no drive letter — write `^/proj/`, not `^C:\\proj\\`) (`grep`/`find`/`ls` with an omitted `path` resolve to the cwd — pi's documented default); other tools (e.g. MCP) have no command or path shape to match against `allow`/`deny`, so they land in the gray zone unless named exactly in `tools` (below).
- `tools: ["ask", "propose_commit"]` is an exact tool-name allowlist for that gray-zone family (MCP/custom tools with no path or command shape, e.g. `ask`, `propose_commit`, `propose_changelog`, `todo`) — a case-sensitive exact match on the tool's registered name bypasses the classifier and returns allow directly. It does not extend to, or interact with, the built-in floor or `denyPaths` (neither covers this family either, so there is nothing to bypass there). Only tool names can be listed: `write` to an `xd://` device (omp's mounted tools) is a `write` call graded by path, not by tool name. The first-run template pre-fills a starter list of omp tools that have no side effect of their own or are gated elsewhere — `ask` (the user is the gate), `todo` (session task list), `wait` (blocks on already-started jobs), `task` (subagents are gated by this extension too), `yield` and `think` (hidden result/scratchpad tools), `checkpoint`/`rewind` (prune session context only; no file or git restore), `recall`/`reflect` (read the configured memory backend). Deliberately absent: `glob`/`ast_grep`/`lsp` (path-scoped reads that would skip `denyPaths` in this family), `web_search` (query text leaves the machine), `retain`/`learn`/`memory_edit`/`manage_skill` (persist content into future prompts), `eval`/`github`/`debug`/`ida`/`security_scan`/`ast_edit` (execute code or mutate state). It is a pre-filled *user declaration*, not a built-in: edit or empty it freely; existing configs are never rewritten, so add the names by hand (or via `/verdict`) to adopt it. An empty list leaves the family entirely classifier-routed.
- `denyPaths` are plain paths (not regexes) you declare **protected**: any tool call touching them — file tools via their path (scope tools via their whole search scope: omitted path/cwd, or a parent directory of a declaration), bash via path tokens extracted from the command string — triggers a **terminal ask** you adjudicate (non-interactive sessions degrade to deny). Not affected by `builtinDenyFloor: false`. The first-run template pre-fills a starter list (`~/.ssh/`, `~/.gnupg`, `~/.mc`, shell rc/profile files), active from the first session after the initial run — a pre-filled user declaration you can edit or empty; existing configs are never rewritten.
  The classifier only ever learns that protected paths *exist*; the paths themselves never leave your machine, and a matched path shows **only** in the local confirm dialog.
- `builtinDenyFloor: false` turns the built-in danger/path floor off entirely (risk accepted by you; the classifier and your rules remain).
- `gateOmpDir: true` (default) is the **forced `.omp` gate**: any file-tool path or bash command touching a `.omp` directory — a `.omp` path segment (case-insensitive) on the lexical or symlink-resolved form, or `.omp` as a bare word in a bash command (`cd .omp`) — triggers a **terminal ask** you adjudicate (non-interactive sessions degrade to deny). Pipeline position: after the built-in floor and your `deny` regexes, before `denyPaths` and `allow` — an `allow` regex cannot skip it. The ask reason returned to the agent carries no path; the matched form shows only in the local confirm dialog. `grep`/`find`/`ls` are checked on their own target (omitted path = cwd) only: a recursive search that merely traverses a nested `.omp` is not an access. Lookalikes (`.ompx`, `x.omp`, `.omp.bak`) do not match; bash matching is token-level like `denyPaths` (substitution/base64/script-content spellings fall through to the classifier). `false` disables it; `/verdict` toggles it too (a project file can also unset it to inherit the global value).
- `autoDeny: false` turns every auto-review deny (built-in danger floor, your `deny` regexes, classifier deny, classifier fail-closed) into a confirmation prompt showing the would-be deny reason. Non-interactive sessions still deny. Default `true`.
- `classifierModel: "provider/model-id"` sets the classifier model (e.g. a fast flash-class model); precedence is flag > env > config > session model (self-reflection); an invalid value falls back to the session model with a one-time warning.
- The spec accepts pi's native `--model` thinking suffix: `"zai/glm-5.3-flash:low"` sets classifier thinking to effort low (default without suffix: thinking explicitly off).
- `explainGateModel: "provider/model-id[:thinking]"` and `explainGatePrompt: "…"` configure the **EXPLAIN-GATE role**, a human-invoked model call behind the ask dialog's **Explain…** option. `explainGateModel` defaults to the session model (an unavailable value falls back to it with a one-time warning; thinking defaults to off); `explainGatePrompt` replaces the built-in default task (`Explain what this action does and why the gate held it for confirmation.`) used when the question is left empty — a typed question replaces the task instead. The call (one attempt, 30 s timeout) carries the sanitized transcript, the full code under review and the gate's stated reason under a fixed system prompt. Its answer is advisory text rendered in the dialog only: it never reaches the agent, the verdict, the audit log or the classifier. Protected-path asks (`denyPaths` hits and the `.omp` gate) never offer **Explain…** — their path plaintext is UI-only (ADR-0002). The dialog's **No, with explanation…** option is available for every ask and forwards your text to the agent in the block reason. Both keys are per-project overridable like the rest; RPC mode and hosts without `ui.custom` get the plain Yes/No confirm.
- `classifierModel: "typesafe/jev-latest"` opts into the bundled **jev decisions adapter** (`extensions/jev-adapter.ts`, loaded with the package; disable it individually with `pi config`). Gray-zone verdicts become one `choice` question against TypeSafe's jev decisions API; the typed answer is synthesized into the usual `<verdict>` text with probabilities and confidence, so timeouts and fail-closed semantics are unchanged. Two transports (`PI_VERDICT_JEV_TRANSPORT`, default `openrouter`): **OpenRouter** sends to `POST /api/alpha/decisions` (an alpha API) and reuses pi's OpenRouter login (`/login openrouter`) with `OPENROUTER_API_KEY` as fallback — no separate typesafe account; **typesafe** sends to TypeSafe's official `POST api.typesafe.ai/v1/systemone` with `TYPESAFE_API_KEY` (self-service at console.typesafe.ai — pi has no typesafe login, so this is that transport's only credential source). The two wire contracts are isomorphic except for the model slug; the TypeSafe API does not report per-call cost (it shows as $0). `PI_VERDICT_JEV_URL` overrides whichever transport is active. Thinking suffixes are meaningless for jev and are ignored. Caveats ([ADR-0003](adr/0003-jev-decisions-adapter.md)): the denyPaths existence hint does not reach jev (denyPaths themselves stay rule-enforced before the classifier); jev treats the transcript as data and "does not treat it as hostile by default" (TypeSafe docs), so adversarial transcript content can move its judgment; omp hosts cannot load the adapter and the setting falls back there.
- `toggleShortcut` rebinds the master-switch toggle key (`null` or empty disables it, not persisted).
- `audit: true` turns on the **verdict audit log** (#54): every gray-zone adjudication appends one self-contained JSONL record to `<agentDir>/verdicts/<sessionId>.jsonl` — timestamp, session id, cwd, model id, tool name + input, action line, thinking level, the full transcript sent, the raw response text, the parsed verdict + reason, source (`model`/`fail-closed`/`protected-path`), shadow-cache probe result, and the degraded flag. Rule-layer allow/deny decisions are never recorded; **protected-path asks are recorded** (#62) — their confirms are user adjudications that grade the denyPaths rules (the record carries the matched path in `detail`). Interactive asks (classifier and protected-path alike) record **ground truth** (#62): the record is written after the confirm resolves, carrying `userAnswer` (`allowed`/`declined`) and `answeredAt` (`ts` stays adjudication time); a non-interactive degraded ask records immediately as its effective deny, without the answer fields. Accepted trade-off of the deferred write: closing pi while a confirm dialog is open loses that ask record (one record per verdict, append-only — no pre-write/rewrite). Records of triggered calls carry an optional `fallback` sub-object when the second layer is configured (#63 — see above for its reading discipline). Retention keeps the 20 most recent session files (pruned at session start). Full fidelity by design: records may contain protected-path plaintext — that stays inside your machine ([ADR-0002](adr/0002-deny-paths-deterministic-ask.md) boundary note); the directory carries no special protection and reads/writes to it are graded like any other path (records can contain untrusted raw model output, including fail-closed failures — treat the directory as sensitive if you read it back). The sink is fail-soft: a write failure never affects or delays a verdict — one warning, then silent for the rest of the session. Never an adjudication input: append-only, never read back into gate decisions (shadow-cache discipline). `/automode` shows `audit: on → <path>` while active. Off by default; no `verdicts/` directory is created unless a recordable adjudication happens with audit on.
- `notifyAllows: true` surfaces every **classifier allow** as an info notification (verdict reason + action line) — the gate's judgment calls become visible, e.g. jev's probability breakdown (`jev: allow 66% (confidence 49%; ask 33%, deny 1%)`). Default `false`: notifications stay limited to what needs your attention (deny/ask/warnings) and passes stay silent. Mechanical passes never notify under this option — allow-rule hits are echoes of your own declarations, and a protected-path confirm's visibility is the dialog itself; complete records live in the verdict audit log instead. Orthogonal to the debug switch: shadow-cache annotations stay debug-only, and with both on the classifier-allow notification appears exactly once (with the shadow suffix). Config-only, new-session semantics.
- `classifierMinConfidence: 0–100` sets the **confidence floor** — the minimum confidence at which the first layer may adjudicate on its own ([ADR-0004](adr/0004-classifier-fallback-cascade.md), #67). A jev verdict with confidence strictly below the floor is **demoted**: the call cascades to the second layer if `classifierFallbackModel` is configured, otherwise it is asked of you directly (non-interactive degrades to deny; any verdict — allow, ask, deny — demotes). At or above the floor the first layer is fully autonomous and nothing extra runs. The floor works standalone — it does not require a second layer. The rendered confidence floors rather than rounds (a true 49.6% renders 49% and cannot slip past a 50 floor), and jev's confidence is hard-required by the adapter (contract drift fails closed). LLM first layers emit no numeric confidence: the floor (and the whole cascade) is inert for them. `null` (the default) = off; invalid values skip into the one-shot warning channel. The old key name `classifierFallbackConfidence` (0.10.0) warns as renamed and is ignored.
- `classifierFallbackModel: "provider/model-id"` adds an opt-in **second-layer classifier** consulted on exactly two occasions: a **demotion** (confidence below `classifierMinConfidence`) and a **fail-closed** first layer. It gets its own 15s-per-attempt budget (the two-tier retry can double it, mirroring the first layer's per-attempt 25s) and, unlike jev, receives the denyPaths existence hint. Resolution is config-only and never falls back to the session model; an unresolvable model warns once per session. High-confidence asks no longer consult it — a confident ask goes straight to you.
- `classifierFallbackMode: "shadow"` (default) — the second layer **records its opinion** (audit `fallback` sub-object + `/automode` counters: `triggered · agreed · would-overrule · errored`) and never changes any verdict: a demoted call is asked of you, a fail-closed deny stands. `"enforce"` — the second layer **adjudicates de novo**, with exactly one carve-out: a demoted first-layer **deny** that the second layer would allow is asked of you instead (never an automatic allow; headless degrades to deny). A failed or unresolvable fallback on a cascaded call falls to you as well — the tier that was to adjudicate is down (headless → deny, one-time warning). Audit reading: the top level keeps **first-layer semantics** (records of non-interactive asks — native, demoted, escalated — carry their effective deny, per the standing convention), `demoted: true` marks floor fires, and the applied verdict lives in `fallback.effective` (enforce rows, failure rows carry the `"ask"` you got). Shadow→enforce flip is a human decision after shadow data ([criteria](adr/0004-classifier-fallback-cascade.md)); config-only, new-session semantics.
- `subagentGate: "off" | "normal" | "auto"` (omp only, default `"off"`) controls the `ask`s raised inside **subagents**. omp creates subagent sessions in-process with no UI, so without this key every subagent ask would degrade to deny. `"normal"`: the confirmation dialog appears on the **root** session's UI (titles and notifications carry a `[subagent <id> (<name>)]` label); if nobody answers within `subagentAskTimeoutMs`, or the root has no UI (e.g. `omp -p`), the ask is resolved without a human. `"auto"`: never prompt; always resolve without a human. `"off"` (default): the gate is inert in subagents — no rule, floor or classifier check runs on their tool calls; set `"normal"` or `"auto"` to gate them. pi has no subagent identity (`ctx.agent`), so pi behavior is unchanged.
  **Resolving without a human** consults `classifierFallbackModel` once, only when the ask came from the classifier (its `ask`, or a demoted/shadowed cascade outcome the second layer allowed, which then applies directly). Only an explicit `allow` permits the call; a deny, ask, error, timeout or an unconfigured/unresolvable second model denies (block tag `subagent-auto`). Asks that did not come from the classifier — protected-path and `.omp` gate asks, and rule/fail-closed/classifier-deny asks that exist only because `autoDeny: false` — always deny, with no path plaintext in notifications or the block reason (ADR-0002). A demoted first-layer deny is never auto-allowed (ADR-0004). Subagent notifications are shown on the root UI with the label. A cancelled subagent run closes its pending root dialog and blocks with `subagent-cancelled`; the second model is not consulted.
- `subagentAskTimeoutMs` (positive integer, default `60000`) is the `"normal"`-mode deadline for the root dialog, measured from enqueue — time spent queued behind another dialog counts. Root dialogs are serialized, so concurrent subagent asks are shown one at a time. **Set omp's `extensionHandlers.toolCallTimeoutMs` (in `config.yml`, default 30000) to at least `subagentAskTimeoutMs + 60000`**: omp pauses a handler's active-work budget only for the session's own dialogs, so a subagent waiting on the root UI keeps spending it, and an expired budget blocks the call (`Extension … timed out`). With `audit: true`, subagent asks record `subagent: { id, name, resolution }` (`human` / `timeout` / `auto`) and second-model resolutions record `fallback.triggeredBy: "subagent-ask"`.
- `rules: ["…"]` are free-text classification rules appended to every classifier prompt (LLM classifiers and the jev adapter, where they extend the verdict question's instructions). Where a rule applies, it takes precedence over the classifier's default criteria. Non-string or empty entries are skipped with a warning.
- **Project config**: when a session's cwd (or an ancestor) contains `.pi/pi-verdict.json` (`.omp/pi-verdict.json` on omp — the dot-dir matches whichever host tree this config lives in), the gate can load it. The nearest file walking up from cwd wins; the walk stops before your home dir and before the agent tree's own root. It is shallow-merged over the global config for that session — every key except `toggleShortcut` (never per-project overridable) and `_hint`. **A project config is applied only when its project is trusted; an untrusted or undecided project config is never applied**, because a repository you clone could otherwise weaken the gate (e.g. `allow`, `builtinDenyFloor: false`, `autoDeny`). When an interactive session starts in a project with a config and no recorded decision, the gate asks: **Trust** (apply it and remember), **Not now** (ignore it this session; asked again next session), or **Never** (ignore it and don't ask again). Decisions are stored per project root (the directory containing the dot-dir; exact match, not subtrees) in `<agentDir>/config/pi-verdict-trust.json`, shaped `{ "trusted": ["/abs/root", …], "untrusted": ["/abs/root", …] }`. Edit it by hand to revoke trust or to be asked again; a malformed trust file is reported and never overwritten. Trust is per root, not per file content: editing a trusted project's config does not re-prompt. Headless sessions and subagents never prompt: an undecided project config is ignored (a subagent follows the decision already stored by the main session).
- **`/verdict` editor**: `/verdict user` / `/verdict local` (bare `/verdict` asks) edits the list keys `allow`, `deny`, `denyPaths`, `tools`, `rules` of the global or project file from the TUI, plus the `gateOmpDir` on/off switch. Only the edited key is rewritten (other keys, order and `_hint` kept); the session reloads the rules right after each save. A project list replaces the global one, so the first project-level add offers a copy of the global list; `× Unset` drops the override. Editing a project file never trusts it — an untrusted project's edits are saved but not applied. A file that is not valid JSON, or whose list key is not an array (or `gateOmpDir` is not a boolean), is refused with a message — fix it by hand.

## Why no built-in allowlist?

Bypass testing of the rule layer ([writeup](../research/rule-layer-security-audit.md)) showed that allowlist robustness is very limited. The built-in layer only makes **deny** claims (the sound direction); allow claims are yours.

## Host notes (pi and oh-my-pi)

pi-verdict runs on both [pi](https://github.com/badlogic/pi-mono) and [oh-my-pi](https://github.com/can1357/oh-my-pi) (omp); the extension self-anchors to whichever agent tree it is installed in. On a dual-install machine the gate follows the extension copy's own location — the mere presence of `~/.omp` never redirects a pi run (and vice versa).

Implementation details worth knowing if you hack on the extension:

- omp 18's `ModelRegistry` has no `complete` method, so the classifier resolves completion through the pi-ai compat module at first gray-zone verdict (`@earendil-works/pi-ai/compat`, which omp's legacy compat layer rewrites to its bundled pi-ai). Resolution or call failures follow the usual fail-closed deny.
- Thinking control is sent in both hosts' native dialects (`thinkingEnabled`/`effort` for pi, `reasoning`/`disableReasoning` for omp); each host reads its own fields and ignores the other's.
- omp installs npm plugins under `plugins/node_modules/<pkg>/` in its config root — under `<agentDir>/` up to omp 18.0, a sibling of `agent/` since omp 18.1. The user-rules config always lives under `<agentDir>/config/` on both layouts.
